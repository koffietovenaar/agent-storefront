# Contributing

Thanks for helping improve this project.

## Before opening an issue

1. Search existing issues and pull requests.
2. Confirm the problem still occurs on the latest supported version.
3. Remove credentials, private data, and unrelated logs from the report.
4. Prepare the smallest reproducible example you can share safely.

## Pull requests

- Keep one change per pull request.
- Add or update tests for behavior changes.
- Update user-facing documentation when the interface changes.
- Explain the validation you performed.
- Link the relevant issue when one exists.

Maintainers may ask for changes before merging. Opening a pull request does not
guarantee acceptance.

## Security

Do not report vulnerabilities in a public issue. Add the project's private
security-reporting route here: `{security contact or advisory URL}`.
